# DataEase 功能对标与吸收建议

> 对标对象：DataEase v3.1.0（Gitee `fit2cloud-feizhiyun/DataEase`，GPL-3.0）  
> 对标产品：本项目（Superset 6.x 血统，Go + React）  
> 结论日期：2026-10-17

---

## 0. 一句话结论

**DataEase 强在「消费端最后一公里」，我们强在「生产端与智能分析」。**  
DataEase 的功能清单里，真正值得我们吸收的不是它的数据准备体系（我们已更强），而是**让做好的东西能被看见、被传播、被交互**的那一层：公共分享、导出、联动/钻取、外部参数、大屏、模板、水印。  
而它的电子表格、数据填报、Calcite 跨源查询，属于另一个产品形态，**不建议追**。

---

## 1. 定位差异（决定了该吸收什么）

| 维度   | DataEase                        | 本项目                                       |
| ---- | ------------------------------- | ----------------------------------------- |
| 血统   | 自研（Spring Boot + Vue + AntV G2） | Superset 6.x 1:1 复刻（Go + React + ECharts） |
| 目标用户 | 「人人可用」的业务人员、运营、管理者              | 数据分析师 + 有 SQL 能力的业务方                      |
| 核心动作 | 拖拽 → 出图 → 分享/投屏                 | 建模 → SQL/语义层 → 图表 → 仪表板 → Agent 问答        |
| 强项   | 大屏、模板、分享、交互、中国式报表               | SQL Lab、67 种引擎、RBAC、Agent 分析闭环            |
| 弱项   | 无 SQL 工作台、语义层薄、AI 仅在 X-Pack     | 消费端功能几乎空白（无分享/导出/联动/大屏）                   |

> **关键判断**：不要按功能清单逐条抄。DataEase 的「数据源 16+ / 图表 40+」我们并不落后（67 引擎 / 67 图表类型），落后的是**发布与消费链路**。

## 4. 明确不建议吸收（含理由）

| 功能                           | 不吸收的理由                                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **电子表格 / 中国式复杂报表**           | 需要 Univer 级 Canvas 表格引擎（500+ 函数、多级表头、合并、条件格式），是 3–6 个月量级的独立子系统，且会把产品拖进「报表工具」红海。我们的替代路径：透视表 + 导出 Excel + 模板              |
| **数据填报（写回业务库）**              | 本质是表单 + 写事务 + 审批流，属于另一个产品（DataEase 也是独立模块）。与「只读分析」的安全模型冲突，会破坏 Agent 只读守卫的前提                                             |
| **Calcite 跨源查询**             | DataEase 用 Java Calcite 做跨库 JOIN；我们若要等价能力，得引入查询联邦层，工程量与稳定性风险都高。替代：物化到同一个库 / 用数据集 SQL 预聚合                                |
| **计算引擎（StarRocks/Doris 加速）** | 属于基础设施选型，不是产品功能。客户有 OLAP 库时我们直连即可（已支持）                                                                                  |
| **200+ 模板市场**                | 这是内容运营，不是研发。先做「模板导入导出 + 6–10 套内置」，验证使用率再投入                                                                              |
| **多组织 / 多租户**                | 除非明确要做 SaaS 多租户，否则 RBAC + RLS 已覆盖 90% 企业场景                                                                              |
| **直接复制 DataEase 代码**         | ⚠️ **DataEase 是 GPL-3.0**，本项目无 LICENSE 文件但沿用 Superset（Apache-2.0）血统。**只能吸收产品设计与交互范式，不可复制源码/样式文件**，否则整个产品有被传染为 GPL 的法律风险 |

## 5. 我们的差异化防守（不要被功能清单带偏）

这四项是我们的护城河，DataEase 短期补不上，应当持续加码而非稀释：

1. **67 种引擎 + EngineSpec 方言层** —— 信创（达梦/人大金仓/GaussDB）+ 云数仓全覆盖。
2. **Agent 分析闭环** —— plan/act/observe 可观测 + 只读 SQL 守卫 + 指标字典 + 一键存图进仪表板 + 会话记忆。DataEase 的 Copilot 只到「对话出图」，没有写回与审计。
3. **RBAC 权限矩阵**（`(action)on(resource)`）—— 比 DataEase 的「菜单权限 + 资源权限」更细，可对齐 Superset 生态。
4. **SQL Lab** —— 分析师入口，DataEase 完全没有。

> 建议的产品叙事：**「有 SQL Lab 的自由度，也有业务人员的一键分享」**。前者我们已经赢，后者就是本轮要补的。

## 6. 建议的落地路线

### 第 1 周：零成本补齐（1–7 项）

- 操作日志页、收藏/最近使用、图表 PNG/CSV 导出、仪表板 PNG/PDF、URL 外部参数、水印、数据源健康检查
- 验收：日志页可筛选导出；图表右键出图；`?f_xxx=` 能初始化筛选；水印可开关

### 第 2–4 周：消费端核心（8–12 项）

- 公共分享链接 → 联动 → 跳转 → 钻取 → 列级脱敏
- 验收：
  - 未登录打开分享链接可见仪表板；过期/错密码被拒；关闭「允许导出」后按钮消失
  - 点击柱状图某维度，其余图表 500ms 内联动过滤，可一键清除
  - 钻取 3 层面包屑可回退
