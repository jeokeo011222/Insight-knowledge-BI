# 智观 BI · 产品优化建议书

> 视角：产品经理 × 数据分析/可视化赛道。聚焦两大领域：**Agent 智能分析**、**可视化设计**。
> 基准：本仓库实况（`backend/internal/ai`、`frontend/src/components/ai`、`深度二次开发详细设计方案.md`）+ 2026 年国内外竞品格局。

---

## 1. 核心判断（TL;DR）

1. **2026 年每家 BI 都有聊天框，聊天框不再是卖点。** 真正拉开差距的是三件事：答案是否**有治理**（权限在执行前生效）、是否**可复现**（同一问题同一答案、可回溯到 SQL）、是否有**语义层**兜底（指标口径唯一）。我们的 RBAC + `sql_safety` + 审计三层恰好踩在前两点上，这是应当放大而非补齐的优势。
2. **行业共识：AI 准确率的上限由语义层决定，不是由模型决定。** Looker 靠 LookML、Snowflake 靠 Semantic Views、Databricks 把 Metric Views 开源进 Spark——「业务口径写下来一次，处处生效」。我们目前只有 dataset 字段描述，**指标口径层是最大缺口**，也是所有 Agent 优化的地基。
3. **从「被动问答」到「主动洞察」是下一站。** Tableau Pulse 的模式（指标波动 → 自动归因 → 推送到 IM）我们具备独特成本优势：**reports/alerts 调度、Slack/邮件投递、insight skill 全都已经建成**，只差把它们串成一条产品链路。这是最便宜的差异化。
4. **可视化侧的机会不在「更多图表类型」，而在「从对话到成图」的闭环速度。** 后端写工具已能自动建图表（`AI 图表 N`）、前端 `AiWriteConfirm` 已有确认闭环，离「用户说一句话 → 图表出现在仪表盘正确位置」只差最后一公里，而这正是 ThoughtSpot Spotter / Fabric Copilot 正在收编的用户心智。

### 2.3 三条行业共识（本文档所有建议的公理）

1. **Fix the context, not the model.** 各家模型能力趋同，拉开差距的是喂给模型的上下文质量（schema 描述、口径、示例问答）。
2. **治理必须在执行前。** 事后审计只能追责，事前拦截才能卖进金融/央国企。
3. **确定性 > 聪明。** 同一问题两次答案不同，是enterprise 采购一票否决项。

## 3. 现状诊断

### 3.1 已建成（护城河，继续加深）

- **Agent Runtime**：reasoning loop、系统提示注入隔离（prompt-injection partition）、步数/成本护栏、run 持久化 + **回滚**（业界少见的写操作安全闭环）；
- **8 个 skill**（nl2sql / sql_explain / insight / chart_design / dupont / trend / structure / yoy_mom），其中杜邦分析已落到 finance 域范式；
- **读写工具分层** + `sql_safety` + 三层审计 + 快照回滚——对应行业共识 2，话术可直接进销售材料；
- 前端 AgentPanel 内嵌仪表盘、步骤时间线流式渲染、SQL 预览、写操作确认；
- 调度/告警/报表 + SMTP/Slack 投递、63 种 viz、grid 编辑器 + TABS、67 引擎——**主动洞察与可视化落地的全部基建就位**。

### 3.2 四大短板（按对用户体验的伤害排序）

| # | 短板 | 用户感知 | 对标 |
|---|---|---|---|
| S1 | **无指标口径层**：字段有描述，但「活跃用户」「GMV」这类口径无处安放 | 问数结果对不上业务口径，信任崩塌，回退到问分析师 | LookML / Metric Views |
| S2 | **单轮问答，无会话**：每次 invoke 独立，不能追问「那上个月呢」「按渠道拆一下」 | 用户被迫每次完整重述问题 | Spotter / Genie 的会话式分析 |

| S4 | **洞察不主动**：insight skill 需要用户来问；报表推送的是静态截图 | 系统有数据却沉默，价值感知低 | Tableau Pulse |

## 4. 优化方向一：Agent 智能分析

### P0-1 指标口径层（Semantic Layer Lite）——所有优化的地基

- **做法**：不照抄 LookML 的重工程。在现有 dataset 之上加 `metrics` 实体（名称、口径表达式、维度白名单、同环比规则、负责人、审核状态），Agent 的 `query_executor` 与 nl2sql 强制从指标字典取口径，禁止模型自由发挥聚合表达式。
- **冷启动**：提供「从现有图表反向提取口径」的引导工具——已保存的 63 种 viz 的 params 里就是现成口径，一键沉淀进字典。
- **验收**：同一问题在两个用户、两个时间发起，返回 SQL 逐字符一致（可复现性测试进 CI）。
- **参照**：Databricks Metric Views GA 后开源进 Spark——证明轻量指标层可以标准件化，不必发明轮子。

### P0-2 分析会话（Session-based Analytics）

- **做法**：`agent_runs` 增加会话概念，前 N 轮的结论（不是全文，是摘要 + 最后一个 QueryContext）作为上下文带入；前端 AgentPanel 改为会话流 + 满足「追问」「下钻」「换个维度」三类高频 follow-up。
- **关键设计**：上下文捕获契约（设计方案 5.4 已有）升级为**双向**——不只把当前图表选择传给 Agent，Agent 产出的图表也能反向「钉」进当前仪表盘（复用刚做完的 TABS/grid 写回）。
- **验收**：从「上季度 GMV」到「按渠道拆一下」到「华南为什么跌」三轮不重述问题。

### P0-3 chart_design 闭环：从「说人话」到「看到图」

- **做法**：insight/nl2sql 结论的数据结构里携带 `QueryContext`，Agent 直接调写工具建图（`AiWriteConfirm` 确认 → 自动选择 viz 类型 → 自动落位到当前仪表盘行/tab）。缺省推荐规则：时间维度→timeseries、分类≤6→bar、占比→pie、两维密度→heatmap——这套规则与我们 `is_timeseries` 语义正好同源。
- **验收**：一句话问数的结果页有「保存为图表」且落位正确；从提问到入盘 ≤ 2 次点击。

### P1-4 主动洞察：指标订阅（Pulse 模式，我们的成本洼地）

- **做法**：新增 `metric_subscription` 实体（指标 + 通道 + 频率 + 异常规则），复用 robfig/cron 调度 + executor + SMTP/Slack 投递；每次执行时跑 anomaly skill（z-score / 环比突变 / 缺数检测），产出 NL 摘要卡片（结论 + 归因 top-N + 一键跳转仪表盘）。
- **卖点**：「系统在下班后替你看了数」，推送进 Slack 的不是截图而是可追问的卡片（点击深链回仪表盘并带 native_filter 预设——URL 分享我们已实现）。
- **验收**：告警 4 / 报表 5 的投递链路上跑通首个 NL 洞察卡片。

### P1-5 归因下钻（driver analysis）

- **做法**：`structure` skill 升级：给定指标突变（时间点、幅度），自动按维度贡献度分解（加性分解 + 排序 top 贡献项 + 显著性过滤），输出「GMV -12%，其中华南贡献 -9pct，主要由 A 渠道下滑」。这是 Tellius 的核心场景，也是业务方最高频的「为什么」。
- **验收**：对 seed 数据的构造性异常（手工调小某渠道），归因 top1 命中。

### P1-6 NL2SQL 自检回环与评测集

- **做法**：generate → EXPLAIN → 执行 → 结果合理性检查（行列数、空值率、与问题类型匹配）→ 失败自动改写一次（最多 1 次，防止烧钱空转，护栏已有步数上限）。同时建 **golden question 评测集**（每域 50 题：问题 / 期望 SQL 特征 / 期望行数区间），进 CI 做回归门禁。
- **参照**：行业调查 Copilot 成功率 76%、命名规范能带来 15-20 个百分点波动——评测集就是我们的「命名规范」杠杆。

### P1-7 成本分级路由

- **做法**：意图分类（问数/解释/闲聊/复杂归因）用小模型或规则先行；简单问数走「语义层编译 + 单次调用」（确定性路线，对齐 Cortex Analyst 的 semantic operator 思路），复杂分析才进完整 reasoning loop。`llm_gateway` 已是单一入口，改造成本低。
- **验收**：P50 延迟与 token 成本各降 ≥ 40%，评测集准确率不降。

### P2-8 IM 分发与嵌入式

- Slack bot token 路径对真实工作区验证（已列差距）→ 补钉钉/企微/飞书 webhook，把 P1-4 的洞察卡片推出去。
- 嵌入式场景：`embedded` 模块已有，Agent 面板按租户降权暴露（只读 skill 子集），是国内 SaaS 付费最快的产品形态。

## 5. 优化方向二：可视化设计

### P0-1 图表智能配色与主题令牌

- **做法**：主题层抽成 design token（品牌色板、语义色、CJK 字体栈、网格密度），一键换肤全站生效；图表色板支持「跟随主题 / 按维度稳定着色」（同一维度值跨图表同色——目前各图独立取色，仪表盘读感割裂）。
- **验收**：切换主题后 dashboard 截图（我们有无头截图基建，验收自动化免费）色板一致；同维度跨图表色值一致。

### P0-2 AI 自动标注（narrative chart）

- **做法**：时序图表增加「洞察层」：AI 自动生成 title 副标、峰值/拐点 callout、异常区间底色标注（数据来自 insight skill 的同一套计算，**算一次两处用**）。
- **参照**：Tableau Pulse 的核心体验就是把「解读」叠在图上；国内小Q 的「智能小报告」同理。
- **验收**：折线图默认展示 1 条自动摘要 + 2 个关键点标注，可一键关闭。

### P1-3 图表类型推荐引擎（schema + 数据分布双驱动）

- **做法**：chart_design 的推荐规则从静态映射升级为「看数据说话」：基数、是否时间列、分布形态、缺失率共同决定推荐列表；探索页保存前给出 top3 推荐 + 理由。
- **验收**：评测集中 80% 的黄金问题，top1 推荐与人工选择一致。

### P1-4 智能布局与仪表盘生成

- **做法**：给 AI 一个「仪表盘编排」skill：输入一组图表 → 输出 rows/tabs 建议布局（KPI 行置顶、时序与构成图分 tab、filter 置顶）。我们刚完成 grid 编辑器 + TABS 写回，`toGridLayout` 就是现成的投影层，AI 只需产出 `DashboardRow[]`。
- **验收**：「给这 6 张图排一个汇报版仪表盘」一次成型，人工微调 ≤ 2 步。

### P1-5 数据故事模式（narrative mode）

- **做法**：仪表盘新增「演示」视图：按 tab/分组顺序全屏翻页，每页叠加一句 AI 摘要与缩放图表；导出为 PDF/PPT（`workbuddy-pptx` 同类能力的自研版）。
- **验收**：汇报场景从「截 8 张图贴 PPT」变为「一键导出」。

### P2-6 视觉打磨清单

- 空状态智能化：空仪表盘给「让 AI 生成分析」入口，而不是 Empty 组件；
- 缩略图联动：报表推送/分享卡片用已建成的无头截图服务生成，首屏即图；
- 大屏模式：4K/电视墙的等比缩放布局（国内政企刚需，竞品普遍收费点）。

## 7. 北极星指标

1. **问数采纳率**：Agent 答案被点击「有用 / 保存为图表」的比例（目标 ≥ 60%，行业基准 76% 为上限参考）；
2. **可复现率**：同问题同 SQL 的比例（目标 100%，差异化卖点）；
3. **主动洞察触达后 7 日回访率**（衡量 Pulse 模式是否建立习惯）；
4. **从提问到图表入盘的中位时长**（目标 ≤ 30s）。

## 8. 主要风险

| 风险 | 缓解 |
|---|---|
| 指标口径层做重了变成第二个 LookML | 坚持「Lite」：表达式 + 白名单 + 审核态三字段起步，UI 由 AI 辅助生成 |
| 会话上下文膨胀推高成本 | 只带结论摘要 + 最后 QueryContext，步数护栏已有 |
| 主动推送变骚扰 | 订阅默认周频 + 异常才推 + 频控与免打扰时段 |
| 与并行开发的 AI 模块冲突 | 本文档为产品建议不改代码；落地时按 `深度二次开发详细设计方案.md` 的模块边界实施 |
